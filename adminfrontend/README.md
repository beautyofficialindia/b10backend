# B10 AI Assistant - Admin Dashboard (Frontend)

This directory contains the internal administration dashboard for the B10 AI Assistant platform. It provides the visual interfaces required for the Sales and Support teams to manage CRM workflows, view analytics, and track leads generated by the AI Chatbot.

---

## Next.js Architecture

The application is built using **Next.js 16** utilizing the **App Router** (`app/` directory).

It heavily utilizes a **Feature-Sliced Design** approach. Rather than having global `components/` or `hooks/` folders containing everything, logic is co-located by business domain inside the `features/` directory.

### Folder Structure

```text
adminfrontend/
├── app/                  # Next.js App Router (Routes, Layouts, Pages)
│   ├── (dashboard)/      # Protected layout group for the internal app
│   ├── login/            # Public authentication route
│   └── showcase/         # Public testing widget route
│
├── features/             # Feature-sliced business domains
│   ├── auth/             # Login forms, Token management
│   ├── knowledge/        # Knowledge Base editor UI (Planned)
│   ├── leads/            # Lead tracking, CRM integration
│   ├── roles/            # RBAC Role assignment (Planned)
│   ├── settings/         # System configurations (Planned)
│   └── users/            # User account management (Planned)
│
├── components/           # Generic, purely presentational UI elements
│   └── ui/               # shadcn/ui base components (Buttons, Inputs, etc.)
│
├── hooks/                # Generic global React hooks (e.g., useMediaQuery)
├── lib/                  # Core configurations (Axios instances, Tailwind utils)
├── services/             # Global external API abstract interactions
├── store/                # Global State Management (Zustand)
└── types/                # Global TypeScript definitions
```

---

## State Management & Data Fetching

- **Data Fetching & Caching**: Handled entirely via **React Query** (`@tanstack/react-query`). This manages loading states, caching, and background refetching automatically.
- **Global UI State**: Managed via **Zustand** (if required for non-server state like sidebar toggles).
- **Form State**: Managed via `react-hook-form` coupled with `zod` for robust schema validation.

---

## Authentication & Route Protection

The frontend uses JWT-based authentication interacting with the Django backend.

### Flow:
1. User authenticates via `/login` (`features/auth`).
2. The backend responds with `access` and `refresh` tokens.
3. The frontend stores these tokens and attaches the `access` token to all subsequent API requests via an **Axios Interceptor** configured in `lib/axios.ts`.
4. If the `access` token expires, the interceptor automatically attempts to rotate it using the `refresh` token.

### Route Protection (RBAC)
- The entire `(dashboard)` route group is protected.
- Unauthenticated users are strictly redirected to `/login`.
- Role-based UI rendering ensures that `Sales` or `Support` staff only see features permitted by the Django backend's Group assignments.

## Testing Strategy

- **Unit/Component Testing**: Handled by **Vitest**. (Targets isolated utility functions and pure components).
- **End-to-End (E2E) Testing**: Handled by **Playwright**. Validates full user flows (Login → Dashboard → CRM updates).
  - *Note: E2E setup is actively being finalized in Phase 6.*

## Local Development Setup

### 1. Requirements
- Node.js 20+

### 2. Installation
```bash
cd adminfrontend
npm install
```

### 3. Environment Variables
Create a `.env.local` file at the root of `adminfrontend/`:
```env
NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1
```

### 4. Running the Development Server
```bash
npm run dev
```
Navigate to `http://localhost:3000` to view the application.

### 5. Build Process
To generate a production-ready static/optimized build:
```bash
npm run build
npm run start
```
